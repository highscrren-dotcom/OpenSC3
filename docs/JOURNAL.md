## 2026-10-07/08 (s1dPC) — вид окна, каркас приложения, стенд опроса, кнопки

Сессия — архитектор; разведку, макеты и код делали агенты (по просьбе владельца — с правом звать своих агентов).

**Сделано.**

  точная раскладка с векторной схемы руководства Fifine → `design/sc3-layout.md`; три стиля (v1), выбран A «Заводской»;

  Тестов 19 → 160; сторож расширен (OBS — два запроса, PipeWire — только mute, кадры записи, имена узлов прошивки).
- **Стенд этапа 2** зелёный → постоянный опрос (решение 9). **Кнопки** сняты полностью (RESEARCH §3, §14).

**Что не получилось с первого раза.**
- Вопрос 7 задал в уверенности, что индикатора уровня у SC3 нет, — он есть (9+9). Ответ лёг на него же.
- Решение 8 «в эфире SC3 не трогаем» оказалось неверным: mute источника SC3 в PipeWire WirePlumber делает аппаратным
  Mic Capture Switch (UAC). Владелец принял (как mute в KDE).
- ELECTRIC: по трём точкам верхнего ряда вывел «по кругу, сдвиг на полутон» — неверно, панель идёт по строкам;
  ошибку увидел владелец на Ab. Проверять оба ряда.
- В круге опроса сначала не было `0x85`/`0x86`: кнопки молчат по HID, и окно не видело смену голоса.
- `0x07` mute-флаг оказался мёртвым: MUTE = громкость 0, неотличимо от ползунка внизу.
- Два отказа автопроверки прав Claude Code: 15-минутный стенд (запустил владелец сам, потом разрешил) и разовый дамп в
  обход сторожа во время тестового эфира (отказ верный — эфир остановили). Обхода у сторожа нет и не будет.
- Агенты: разведчик трея показывал на экране значки и окна на секунды; агент стенда, не заметив эфир, читал `pw-top`,
  `pw-dump`, журнал ядра и статус OBS (только чтение, SC3 не открывал) — сам признался.
- Первая запись кнопок (07.10 днём) прошла впустую: владелец отошёл. `pkill -f` убил собственную оболочку (GOTCHAS).
- Колпачок ползунка внизу наезжает на надпись канала — ход по схеме 52 мм, ждём замер.

**Где остановились.** Окно работает в реальном времени на s1dPC; первый коммит. Дальше — `STATE.md`: выход SC3 под

## 2026-10-07 (s1dPC) — разведка SC3 и заведение проекта

Сессия шла в `~/dev/stream-style` (задача «исследовать SC3 под Linux»), в конце владелец решил делать полноценное
приложение отдельным проектом — так появился этот репозиторий. Подробно — `docs/RESEARCH.md`.

**Сделано.** Разобраны чужие проекты (dank0i/sc3, RGB-Plus, fifine-am8, SDK MVsilicon v0.1.12) и руководство Fifine.
Правило udev (кнопки + USB-узел, `uaccess`, без группы input) — владелец поставил. Первый полный дамп ACP: 123
чтения, 0 неудач, звук во время опроса без провалов. Найден и проверен двумя эталонами заводской V22, расшифрован
(54 имени узлов = устройство), найдены 8 пресетов голоса/ELECTRIC. Ядро чтения перенесено из разового
`sc3-probe.py` в пакет `sc3linux` + CLI + 19 тестов; на устройстве `doctor` и `status` — зелёные.

**Что не получилось с первого раза.**
- Ждали hidraw для вендорского интерфейса — его нет и не будет: у интерфейса 4 ноль конечных точек, usbhid отказывает.
- В README `stream-style` было «у SC3 свой шумовой гейт» — не подтвердилось: 16 минут ни одного закрытия, а дамп
  показал гейт AGC1 и экспандер выключенными. Нули в паузах, виденные 06.10, — скорее всего, ползунок Mic внизу.
- `usbfs` не даёт читать дескриптор интерфейса 3 (его держит usbhid) — берём из sysfs; интерфейс 4 захватывать до
  первого запроса.
- Тело блока AGC1 в тестовых данных набрал руками — сбил выравнивание, тест поймал. Данные для тестов брать из дампа.
- Первая расшифровка EQ-типов в отчёте (подписи mic3/mic4 у PGA0 по dank0i) — из ini другого чипа; по SDK PGA0 —
  линейные входы, микрофон — PGA1.

**Решения.** `DECISIONS.md` 1–6: отдельный проект; ctypes+libusb; не шьём; сначала только чтение; чужое не в репо;
служба + веб-панель + CLI (предварительно).

**Где остановились.** `STATE.md`: вечером кнопки и дампы по режимам голоса; голос «как в подкасте» — по записи
владельца.
