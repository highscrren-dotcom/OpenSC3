# CLAUDE.md — sc3-linux

Приложение под Linux для микшера **fifine AmpliGame SC3** (USB `3142:0c33`, чип MVsilicon BP1048B2): видеть и
менять его состояние по USB (протокол ACP), кнопки → действия, профили звука, связь с OBS. Отдельный проект с
07.10.2026; разведка начиналась в `~/dev/stream-style` (оформление стримов владельца).
Машина разработки и единственная целевая пока — `s1dPC` (CachyOS, KDE Plasma 6.7 Wayland, PipeWire, OBS 32).
Пишем по-русски; README — на двух языках (англ. основной, `README.ru.md`).

## «Продолжаем» и «закрываем» — порядок из `docs/WORKFLOW.ru.md`

**«Продолжаем»**: `STATE.md` → последняя запись `docs/JOURNAL.md` → `git log`/`status` → **проверить состояние
исполнением** (`python3 -m sc3linux doctor`, тесты) → доложить в нескольких строках и начать.
**«Закрываем»**: проверить исполнением → перезаписать `STATE.md` → дописать запись в `JOURNAL.md` → коммит
**только по слову владельца** → сказать, чем продолжать.

## ⛔ Устройство — жёсткие правила (причины — `docs/GOTCHAS.md`, `docs/RESEARCH.md` §4)

1. **Не прошивать.** Никаких SET/GET_REPORT(Feature) — это вход в загрузчик. Никаких `0x01` (сон/сброс), `0x11`
   (запись во флеш), `0xFB`–`0xFF` (OTA и др.), узлов выше `0xB6` (вешают ACP). Никаких `set_configuration`,
   `reset`, `set_interface_alt_setting`, отцепления драйверов — рвёт звук. Сторож — `tests/test_safety.py`.
2. **Запись в SC3** (любой кадр с `LEN > 0`) — только по явному разрешению владельца в текущем разговоре, вне
   эфира, отдельным белым списком с тестами. Сейчас в коде записи нет вовсе (решение 4).
3. **Эфир.** Перед любым обращением к SC3 по ACP — убедиться, что эфир и запись не идут (`ss -tnp` у OBS или
   `GetStreamStatus`/`GetRecordStatus`). OBS во время эфира не трогать.
4. **Не опрашивать часто.** Процессор SC3 загружен на ~87 %; у RGB-Plus частый опрос подвешивал микшер и звук.
   Постоянный опрос — не чаще раза в 0,5 с и только после стенда на 15 минут (см. `docs/PLAN.md`).
5. **sudo — только владелец.** Давать готовые команды для **fish** (heredoc в fish не работает).
6. **Чужое в репо не класть:** прошивку Fifine, её расшифровку, пресеты и имена узлов из неё, дампы с устройства
   (в них имена узлов). `firmware/` и `dumps/` — в `.gitignore`. В тестах — синтетические данные.
7. **Чужой код** — в отдельную пустую папку, запускать только после прочтения.

## Проверки

```fish
python3 -B -m unittest discover -s tests -t .   # без железа
ruff check .
python3 -B -m sc3linux doctor                   # без обращения к устройству
python3 -B -m sc3linux status                   # ~20 чтений ACP — только вне эфира
```

## Каталоги

- **`sc3linux/`** — пакет: `protocol.py` (кадры, белый список, разбор), `usb.py` (libusb через ctypes — единственный,
  кто говорит с USB), `device.py` (проверка и чтения), `layouts.py` (смысл полей по SDK), `cli.py` (`sc3 …`).
- **`tests/`** — unittest, поддельное устройство `fake.py`.
- **`udev/`** — правило доступа (установлено в `/etc/udev/rules.d/` 07.10).
- **`docs/`** — `RESEARCH.md` (разведка 07.10: протокол, карта управления, прошивка, пресеты), `PLAN.md` (замысел
  приложения и этапы), `DECISIONS.md`, `GOTCHAS.md`, `JOURNAL.md`, `WORKFLOW*.md`.
- **`research/`** — разовые скрипты разведки (звук, разбор прошивки); не пакет, ruff их не проверяет.
- **`firmware/`, `dumps/`** — локально, вне git.
- **`STATE.md`** — где проект сейчас (перезаписывается).
